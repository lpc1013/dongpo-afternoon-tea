## 5. 怎么再产

```
写 tag 与提示词到 tools/prompts_img.tsv（tab 分隔）
写 tools/job_img.json = {"ratio":"16:9","tags":["a","b","c"]}
tabbit-cli nodejs --task jmimg --timeout-ms 180000 --request-id w$(date +%s) < tools/jm_multi.js
python tools/cutout.py <tag-1> <tag-2> ...
python tools/icon_pack.py ico- alt-      # 图标包
python tools/portrait_pack.py            # 立绘状态集
python tools/measure_plaques.py sc-      # 量空白匾
python tools/sheet.py out.png "ico-*.webp" "alt-*.webp"   # 联络表
```

`--task` **一律写 `jmimg`**：换名字 tabbit 就会另开一个即梦页，多页吃内存。
驱动会复用同一个页，日志里 `pageCount` 应当始终是 1。

## 33. 关闭浏览器：正解是 Playwright，不是 taskkill

`taskkill //F` 是强杀，**Chromium 来不及清 `%TEMP%\scoped_dir*`，缓存会越堆越多**
（实测我强杀两轮，`scoped_dir` 反而从 103 涨到 149）。
`taskkill` 不带 `/F` 也没用——助手进程没有窗口、收不到 WM_CLOSE，Windows 直接回「只能用 /F」。
**正解**：`tools/browser_down.sh`（内含 `tools/jm_quit.js`）走
`context.close()` → `browser.close()`，实测 `scoped_dir` 归 0、不堆缓存。
**注意**：关完若仍有浏览器进程存活，先看 `diagnose` 的 `activeTask`——
多半是**另一个会话的任务占着**（本轮就是 `sfxdl` 那个音效任务），那就不是你的进程，别去杀。

§38 说"剩下 21 个 tag 从侧栏够不到"——现在够得到了，但**不是原来那条路**。
资产页 `/ai-tool/asset` 才是全部历史，摸出来的实情：

- **每一格是一张图，不是一批**；点进去详情里有整条提示词，还有一个「技能n/4」计数器——**这个计数器就是序号 n**，

- **方向键不跨批**。我先前记成"ArrowRight 逐张跳"，实测它只在本批四张里循环（slot 4→1→2→3→4、提示词一个字都不变），
  所以"点一次然后一路按右"是错的，必须**逐格点**。
- 详情里那张大图**懒加载**，而且**常常比提示词文字先渲染**：只等图不等字，会读到"有高清、认不出 tag"，
  实测前 6 格全 `matched:"无"`。轮询要**同时等到 `naturalWidth>=700` 的图和 body 里的「提示词」三字**。
- 资产页那张原件的 URL **不一定带 `aigc_resize:` 尺寸段**（生成页预览一定带）。照搬生成页的过滤 → 连跑 125 格 `hits` 恒为 0。
  只按「`cfz/<32hex>` 对象 id + `naturalWidth>=700`」认。
- **跨轮省时的关键**：`tools/hd_map.json` 记 `<对象 id> -> {tag,n}` 或 `{skip:1}`。
  已认出的格子下一轮不再点击。没有这本账，每轮 150 秒全耗在重点头上那几十张已收完的格子上
  （实测 `got 0 / clicked 46` 就是这个）。**记 skip 之前必须先确认详情真的打开了**（body 里有「提示词」三字），
  否则一次渲染慢就把好格子永久跳过了。

### 真正的缺口是产图和代码之间那 19 条

`行旅数据.js` 的 `BOARDS` 里 `fx-*` 只有 10 条，而 `素材/叠字框.json` 已经 **29 条**。
他们自己的注释写着「**手抄一张表一定会漂** —— 所以 validate_cards 有一条断言拿这张表去对 叠字框.json，

```
python tools/emit_boards.py
→ 东坡行旅/素材/叠字框-建议BOARDS.js   （28 条有 face + 1 条只有 alt）
```

生成的是 `var BOARDS_SUGGESTED = { ... }`，**整段可以替换过去**，每行后面带着屏名、容量、倾角和注意事项。
脚本只读 `叠字框.json`、只写那一个文件，**不碰 `行旅数据.js`**（产图侧不动代码是铁律）。
生成完用 `node -e "eval(...)"` 解了一遍：28 条、无越界框、格式全对。

### 顺手纠正了一个语义混淆

代码里 `BOARDS` 的第 5 个元素 `"light"` 是**只管副题那一行**的（`行旅.js` 里 `lt` 只加在 `.subw` 上）。
我第一版 `emit_boards.py` 是拿"浅色字"三个字去子串匹配的，结果把 `fx3-dz-banquet-b-3` 也标成了 `light`——
**但那条是"匾心自己在暗部、堂名要用浅色字"，`light` 管不到匾上的字。**
改成 `叠字框.json` 里两个显式字段，不再猜：

| 字段 | 意思 | 导出成 |
|---|---|---|
| `副题浅底: "light"` | 匾下面那条檐下带/地面是暗的 | BOARDS 第 5 个元素 `"light"` |
| `匾面浅底: "light"` | 匾心自己在暗部 | 只写注释：**堂名要用浅色字，light 管不到** |
| `匾面浅底: "dark"` | 匾心近乎纯白（儋州黎市） | 只写注释：堂名要用深色字 |

重跑之后 `light` 只剩 `fx2-dz-hub-b-3` 一条，正确。
